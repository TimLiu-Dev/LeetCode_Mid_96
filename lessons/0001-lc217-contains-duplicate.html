Contains Duplicate

View on LeetCode ↗

Problem Description

Given an integer array nums, return true if any value appears at least twice in the array, and return false if every element is distinct.

🗣️
Plain-English Translation:

"Are there any duplicate twins in this list? If even a single number appears twice, immediately return true. If every number is 100% unique, return false."

Official Examples

Example 1:
Input: nums = [1,2,3,1]
Output: true
Element 1 occurs at index 0 and 3.
Example 2:
Input: nums = [1,2,3,4]
Output: false
All elements are distinct.
Example 3:
Input: nums = [1,1,1,3,3,4,3,2,4,2]
Output: true
Multiple duplicate clusters exist.
Official Constraints:
  • 1 <= nums.length <= 105 (N is up to 100,000 → O(N²) will TLE)
  • -109 <= nums[i] <= 109 (Values span negative and positive 32-bit range)
The 3 Canonical Input Shapes (Mental Boundary Checks):
1. Minimum Base Case
nums = [42]
Length = 1. A single element can never contain duplicates. Guaranteed false in O(1).
2. Best-Case Early Exit
nums = [7, 7, 1, 2, 3]
Duplicate appears at index 1. Algorithm halts on 2nd step, avoiding scanning the remaining elements.
3. Worst-Case Full Scan
nums = [1, 2, 3, ... 10⁵]
All elements distinct. Forces full linear traversal and hash set reaches max O(N) capacity.

The Mental Model & "Explain Like I'm 12"

🏰 The Real-World Analogy

The VIP Nightclub Bouncer & The Stamp Checklist

Imagine you are a bouncer guarding the front door of a crowded VIP party. Guests arrive one by one, each wearing a numbered sports jersey. Your job is simple: sound the alarm the moment anyone tries to enter who has already entered before.

The naive bouncer lets a guest in, but for every new arrival, walks into the dark, crowded dance floor and compares the newcomer against every single person dancing inside. If there are 1,000 guests, that bouncer makes hundreds of thousands of exhausting comparisons.

The master bouncer keeps a digital tablet with a checklist (HashSet) right at the door. When guest #17 walks up:

  1. Look at the tablet: is #17 checked?
  2. If YES: Stop them immediately! Duplicate detected (return true).
  3. If NO: Check off #17 in $O(1)$ time, let them in, and look at the next person.
💡 The "A-Ha!" Switch

Stop Searching Forward; Store What You've Seen

Beginners mentally search forward into the future array ("Does any later element match this one?"). The algorithmic breakthrough is to look backward at a persistent memory record. As you step through each element, the only question you ask is: "Did I already record this in my seen set?"

02
Algorithmic Contrast

The Naive Trap (Red) vs. Optimal Breakthrough (Green)

The Brute Force Trap O(N²) Time • O(1) Space

The Nested Loop Pair-Scanner

The candidate nests two loops, checking every pair (i, j): 

for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        // ❌ CPU CYCLES WASTED HERE:
        // Comparing nums[i] with elements already 
        // proven unique against earlier entries!
        if (nums[i] == nums[j]) return true;
    }
}
return false;
Why it fails in interviews:

For $N = 10^5$, $\frac{N(N-1)}{2} \approx 5 \times 10^9$ operations. At standard CPU throughput ($10^8$ ops/sec), this takes 50 seconds. The interview platform terminates with Time Limit Exceeded (TLE).

The Optimal Breakthrough O(N) Time • O(N) Space

The One-Pass HashSet Memory Trade

We purchase $O(N)$ auxiliary memory to reduce the lookup time of previously seen items from $O(N)$ to $O(1)$: 

val seen = hashSetOf<Int>()
for (num in nums) {
    // ✅ $O(1)$ Hash Bucket Lookup:
    if (!seen.add(num)) {
        return true // Duplicate found immediately!
    }
}
return false
The Space-Time Bargain:

For $N = 10^5$, storing $10^5$ integers consumes only ~4MB of RAM. In exchange, the execution finishes in 15 milliseconds. A 3,000x speedup!

Asymptotic Trade-off Matrix Target Bound: O(N) Time
Approach Best Time Average Time Worst Time Space Complexity Interview Verdict
1. Brute Force (Nested Loops) O(1) O(N²) O(N²) O(1) ❌ Rejected (TLE on large inputs)
2. Sorting + Adjacent Scan O(N log N) O(N log N) O(N log N) O(1) or O(N)* ⚠️ Suboptimal (Mutates array, slower)
3. Optimal: One-Pass HashSet O(1) O(N) O(N) O(N) ✅ Optimal Production Standard
*Note: In-place sort (e.g. Dual-Pivot Quicksort in Java primitives) mutates the input array, violating API immutability contracts in production environments.

Solution Evolution & Production Code

From Brute Force to Optimal & Interactive Sandbox

Approach:
Time: O(N) | Space: O(N) • ★ Production Standard 
class Solution {
    /**
     * Approach 1: Brute Force (Nested Loops)
     * 
     * Time Complexity:  O(N^2) - Scans all N*(N-1)/2 pairs.
     * Space Complexity: O(1)   - Operates in-place with zero memory overhead.
     * 
     * LeetCode Status: Time Limit Exceeded (TLE) on N = 10^5 (~50 seconds).
     */
    fun containsDuplicate(nums: IntArray): Boolean {
        val n = nums.size
        for (i in 0 until n) {
            for (j in i + 1 until n) {
                if (nums[i] == nums[j]) {
                    return true
                }
            }
        }
        return false
    }
}
Brute Force Engineering Tradeoff:
  • Why it exists: The simplest possible solution requiring zero extra data structures. Useful for tiny arrays ($N < 50$).
  • The Failure Point: Performs $N(N - 1) / 2$ comparisons. At $N = 10^5$, that is $pprox 5 \times 10^9$ operations. Modern CPUs handle $pprox 10^8$ operations per second, taking ~50 seconds and guaranteeing a LeetCode Time Limit Exceeded (TLE).
  • Interview Use: State this in your first 30 seconds to anchor the baseline, then immediately transition: "Because $N$ can reach $10^5$, $O(N^2)$ will timeout. Can we trade space for time?"
class Solution:
    """
    Approach 1: Brute Force (Nested Loops)
    
    Time Complexity:  O(N^2) - Quadratic pair comparisons across the array.
    Space Complexity: O(1)   - Pure in-place index traversal.
    """
    def containsDuplicate(self, nums: list[int]) -> bool:
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                if nums[i] == nums[j]:
                    return True
        return False
Python Brute Force Breakdown:
  • CPython Dispatch Overhead: In interpreted Python, nested bytecode loops execute with heavy function frame overhead, timing out on even smaller inputs ($N \ge 10^4$).
  • Bounds Check: Starting the inner loop at range(i + 1, n) avoids comparing an element to itself or repeating already-compared pairs.
class Solution {
    /**
     * Approach 1: Brute Force (Nested Loops)
     * 
     * Time Complexity:  O(N^2) - Compares each element with all subsequent elements.
     * Space Complexity: O(1)   - Direct primitive array access.
     */
    public boolean containsDuplicate(int[] nums) {
        int n = nums.length;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (nums[i] == nums[j]) {
                    return true;
                }
            }
        }
        return false;
    }
}
Java Brute Force Breakdown:
  • Pure Primitive Access: Operates entirely on raw primitive int[] without GC pressure or object allocations, demonstrating that the bottleneck is purely CPU instruction count.
class Solution {
    /**
     * Approach 2: Better (In-Place Sorting & Adjacent Scan)
     * 
     * Time Complexity:  O(N log N) - Dual-Pivot Quicksort + O(N) adjacent scan.
     * Space Complexity: O(1)        - In-place primitive sort (or O(log N) stack frames).
     * 
     * Interview Follow-Up: "What if memory is strictly constrained and O(N) 
     * auxiliary space is forbidden?" -> This is the winning answer.
     */
    fun containsDuplicate(nums: IntArray): Boolean {
        nums.sort() // In-place Dual-Pivot Quicksort
        for (i in 1 until nums.size) {
            if (nums[i] == nums[i - 1]) {
                return true
            }
        }
        return false
    }
}
Sorting Tradeoff Analysis:
  • Core Principle: Sorting automatically groups all identical values adjacent to each other. A single linear pass nums[i] == nums[i - 1] verifies duplicates.
  • Space Advantage: Avoids allocating an $O(N)$ hash table. Essential for embedded systems, high-frequency low-allocation engines, or severely memory-constrained devices.
  • Side-Effect Caveat: Mutates the input array nums. In multi-threaded concurrent applications, mutating shared input can cause subtle race conditions unless callers pass copies.
class Solution:
    """
    Approach 2: Better (In-Place Sorting & Adjacent Scan)
    
    Time Complexity:  O(N log N) - Built-in Timsort algorithm.
    Space Complexity: O(1)        - In-place sort (O(N) worst-case Timsort buffers).
    """
    def containsDuplicate(self, nums: list[int]) -> bool:
        nums.sort()  # In-place Timsort modifies list in C
        for i in range(1, len(nums)):
            if nums[i] == nums[i - 1]:
                return True
        return False
Python Sorting Breakdown:
  • nums.sort() operates in C at near-hardware speeds using Timsort.
  • Passes all LeetCode test cases easily (~15ms) without allocating Python set objects.
import java.util.Arrays;

class Solution {
    /**
     * Approach 2: Better (In-Place Sorting & Adjacent Scan)
     * 
     * Time Complexity:  O(N log N) - Arrays.sort() on primitives uses Dual-Pivot Quicksort.
     * Space Complexity: O(1)        - In-place (O(log N) recursion call stack).
     */
    public boolean containsDuplicate(int[] nums) {
        Arrays.sort(nums); // Dual-Pivot Quicksort by Vladimir Yaroslavskiy
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] == nums[i - 1]) {
                return true;
            }
        }
        return false;
    }
}
Java Sorting Breakdown:
  • Arrays.sort(int[]) avoids object boxing overhead and uses primitive Dual-Pivot Quicksort with zero heap allocations.
  • Great interview defense when asked how to minimize JVM Garbage Collection pauses.
class Solution {
    /**
     * Approach 3: Optimal (One-Pass HashSet) - Production Gold Standard
     * 
     * Time Complexity:  O(N) - Single linear traversal with O(1) average lookup/insert.
     * Space Complexity: O(N) - Stores at most N distinct integers in the HashSet.
     */
    fun containsDuplicate(nums: IntArray): Boolean {
        // HashSet backed by a hash table for O(1) amortized membership test
        val seen = hashSetOf<Int>()

        for (num in nums) {
            // hashSetOf.add() returns false if the item was ALREADY present
            if (!seen.add(num)) {
                return true
            }
        }

        return false
    }
}
Kotlin Senior Engineering Breakdown:
  • nums: IntArray: Directly maps to Java's unboxed primitive int[], avoiding object overhead during indexing.
  • hashSetOf<Int>(): Instantiates a standard java.util.HashSet. Boxing occurs from primitive Int to java.lang.Integer when inserting into the set.
  • !seen.add(num): Highly idiomatic in Kotlin. Set.add() atomically checks for membership and inserts; if the element is already present, it returns false without mutating the set.
  • Alternative 1-liner: nums.size != nums.distinct().count() or nums.toSet().size < nums.size. Interview warning: While concise, the one-liner always scans the entire array without early exit capability, wasting CPU cycles on test cases like [1, 1, ...].
class Solution:
    """
    Approach 3: Optimal (One-Pass HashSet) - Production Gold Standard
    
    Time Complexity:  O(N) - Single pass with O(1) amortized hash lookups.
    Space Complexity: O(N) - Stores up to N integers in the set.
    """
    def containsDuplicate(self, nums: list[int]) -> bool:
        seen = set()
        
        for num in nums:
            if num in seen:
                return True
            seen.add(num)
            
        return False
Python Senior Engineering Breakdown:
  • seen = set(): Python's built-in set is implemented as an open-addressing hash table with perturbation shift probing.
  • if num in seen:: CPython executes the sq_contains slot via the C-level set_contains function, delivering near-native $O(1)$ amortized lookup speeds.
  • One-liner comparison: return len(nums) != len(set(nums)). In Python, this one-liner is written in pure C and can benchmark faster for small arrays, but allocates the full set unconditionally. The iterative loop with early exit is superior when duplicates occur early in massive datasets.
import java.util.HashSet;
import java.util.Set;

class Solution {
    /**
     * Approach 3: Optimal (One-Pass HashSet) - Production Gold Standard
     * 
     * Time Complexity:  O(N) - Linear scan; each add/contains is O(1) average.
     * Space Complexity: O(N) - Holds up to N elements in the hash set.
     */
    public boolean containsDuplicate(int[] nums) {
        // Pre-size the set if N is known to prevent rehashing overhead
        Set<Integer> seen = new HashSet<>();

        for (int num : nums) {
            // Set.add(E) returns false if the element was already present
            if (!seen.add(num)) {
                return true;
            }
        }

        return false;
    }
}
Java Senior Engineering Breakdown:
  • Set<Integer> seen = new HashSet<>(): Programming to the interface (Set) rather than concrete implementation allows flexible refactoring.
  • !seen.add(num): In Java, HashSet.add() delegates directly to HashMap.put(key, PRESENT) == null. Returning false guarantees the key was already mapped.
  • Memory footprint & boxing: Each boxed Integer occupies 24 bytes on a 64-bit JVM (12-byte header + 4-byte int + 4-byte padding + 8-byte reference). For an ultra-constrained environment, a primitive specialization like FastUtil's IntOpenHashSet saves ~70% RAM.
  • Collision Resolution: Java 8+ transforms linked list buckets into balanced Red-Black trees when bucket length exceeds TREEIFY_THRESHOLD = 8, keeping worst-case lookup at $O(\log k)$.
